# Описание микросервиса Brigade Service

## Общее описание

**Brigade Service** — микросервис, предназначенный для управления бригадами инспекторов в системе контроля и мониторинга. Микросервис реализован на языке Go и является частью распределённой микросервисной архитектуры.

### Основные функции

1. **Создание бригад** — формирование бригады из списка инспекторов с валидацией их ролей.
2. **Получение информации о бригадах** — просмотр данных о конкретной бригаде или списка всех бригад.
3. **Управление статусами бригад** — автоматическое обновление статуса бригады при получении событий о задачах.
4. **Интеграция с внешними сервисами** — взаимодействие с user-service для получения данных о пользователях.

---

## Архитектура микросервиса

### Технологический стек

| Компонент | Технология |
|-----------|------------|
| Язык программирования | Go |
| База данных | PostgreSQL |
| Брокер сообщений | Apache Kafka |
| HTTP-сервер | Собственная реализация (golib) |
| ORM/Query Builder | sqlx |
| Миграции | goose |

### Слои приложения

1. **API Layer** (`api/`) — обработка HTTP-запросов, маршрутизация.
2. **Service Layer** (`service/brigade/`) — бизнес-логика управления бригадами.
3. **Data Access Layer** (`database/brigade/`) — работа с базой данных PostgreSQL.
4. **Integration Layer** (`cluster/`) — интеграция с внешними сервисами (user-service) и обработка событий (task events).

## API микросервиса

### REST API Endpoints

| URL | Тип запроса | Краткое описание | Параметры |
|-----|-------------|------------------|-----------|
| `/brigades` | POST | Создание новой бригады | **Body (JSON):** `InspectorIDs: []int` — массив идентификаторов инспекторов |
| `/brigades/{id}` | GET | Получение бригады по идентификатору | **Path:** `id: int` — идентификатор бригады |
| `/brigades` | GET | Получение списка всех бригад | Без параметров |


### Статусы бригады

| Код | Название | Описание |
|-----|----------|----------|
| 0 | Unknown | Неизвестный статус |
| 1 | Idle | Свободна (ожидает задания) |
| 2 | OnTask | На задании |
| 3 | Archived | В архиве |

## Интеграции

### Kafka Consumer (События задач)

Микросервис подписан на топик событий задач и обрабатывает следующие типы событий:

| Тип события | Описание | Действие |
|-------------|----------|----------|
| `EventTypeAdd` (1) | Добавление задачи | Нет действий |
| `EventTypeStart` (2) | Начало выполнения задачи | Установка статуса бригады `OnTask` |
| `EventTypeFinish` (3) | Завершение задачи | Установка статуса бригады `Idle` |

### HTTP Client (User Service)

Микросервис взаимодействует с `user-service` для:
- Получения информации о пользователях по их идентификаторам.
- Валидации ролей пользователей (проверка, что пользователь является инспектором).

## Схема базы данных

### Таблица `brigades`

| Поле | Тип | Описание |
|------|-----|----------|
| id | INT (PK, AUTO) | Идентификатор бригады |
| status | INT (FK) | Статус бригады |
| created_at | TIMESTAMPTZ | Дата создания |
| updated_at | TIMESTAMPTZ | Дата обновления |

### Таблица `brigade_members`

| Поле | Тип | Описание |
|------|-----|----------|
| brigade_id | INT (PK, FK) | Идентификатор бригады |
| inspector_id | INT (PK) | Идентификатор инспектора |
| assigned_at | TIMESTAMPTZ | Дата назначения в бригаду |

### Таблица `brigade_statuses`

| Поле | Тип | Описание |
|------|-----|----------|
| id | INT (PK, AUTO) | Идентификатор статуса |
| name | TEXT | Название статуса |

## Диаграмма классов

Диаграмма классов микросервиса представлена в файле `class_diagram.puml` в формате PlantUML.

### Описание диаграммы классов

Диаграмма классов отражает архитектуру микросервиса Brigade Service и включает следующие основные компоненты:

1. **Пакет main** — содержит структуру `App`, которая является точкой входа приложения и отвечает за инициализацию всех компонентов: подключение к базе данных PostgreSQL, настройку Kafka consumer, создание сервисов и запуск HTTP-сервера.

2. **Пакет api** — реализует REST API микросервиса:
   - `ServerBuilder` — строитель HTTP-сервера с поддержкой middleware (метрики, восстановление после паники, логирование ошибок).
   - `BrigadeHandler` — набор обработчиков HTTP-запросов для операций с бригадами.

3. **Пакет service/brigade** — содержит бизнес-логику:
   - `Service` — основной сервис, реализующий операции CRUD для бригад и обработку событий Kafka.
   - `Repository` и `UserService` — интерфейсы для абстрагирования от конкретных реализаций.
   - Модели данных: `Brigade`, `Inspector`, `CreateBrigadeRequest`, перечисление `Status`.

4. **Пакет database/brigade** — слой доступа к данным:
   - `RepositoryImpl` — реализация интерфейса `Repository` для работы с PostgreSQL через транзакции.
   - `DBBrigade` и `Member` — сущности базы данных.

5. **Пакет cluster/user** — интеграция с user-service:
   - `Client` — HTTP-клиент для получения информации о пользователях.
   - `User` — модель пользователя с перечислением ролей `Role`.

6. **Пакет cluster/task** — модели для обработки событий задач из Kafka:
   - `Event` — событие с типом, датой и информацией о задаче.
   - `Task` — модель задачи с полями статуса, идентификатора бригады и временными метками.

7. **Пакет config** — конфигурация приложения:
   - `Settings` — корневая структура настроек.
   - `Databases`, `Kafka`, `Topics`, `Cluster` — вложенные структуры для группировки параметров.

Диаграмма демонстрирует применение принципов чистой архитектуры: бизнес-логика изолирована от инфраструктурных компонентов через интерфейсы, что обеспечивает тестируемость и возможность замены реализаций.

## Конфигурация

Микросервис настраивается через JSON-конфигурацию со следующими параметрами:

```json
{
  "port": 8080,
  "databases": {
    "postgres": "postgres://user:%s@localhost:5432/brigades?sslmode=disable",
    "kafka": {
      "brokers": ["localhost:9092"],
      "topics": {
        "tasks": "task-events"
      }
    }
  },
  "cluster": {
    "userService": "http://user-service:8080"
  }
}
```

## Запуск микросервиса

### Переменные окружения

| Переменная | Описание |
|------------|----------|
| `POSTGRES_PASSWORD` | Пароль для подключения к PostgreSQL |
| `ENVIRONMENT` | Окружение (local, dev, prod) |

### Docker

Микросервис может быть запущен в Docker-контейнере с использованием предоставленного `Dockerfile`.

```bash
docker build -t brigade-service .
docker run -e POSTGRES_PASSWORD=secret -p 8080:8080 brigade-service
```

## Особенности реализации

1. **Транзакционная безопасность** — все операции с базой данных выполняются в рамках транзакций.
2. **Graceful Shutdown** — корректное завершение работы с закрытием всех соединений.
3. **Автоматические миграции** — при запуске применяются миграции базы данных.
4. **Событийная архитектура** — статус бригады обновляется автоматически при получении событий из Kafka.
5. **Валидация данных** — проверка ролей пользователей при создании бригады.
